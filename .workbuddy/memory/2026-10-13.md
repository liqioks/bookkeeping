## 下午补充：页面「点了没反应」故障（我自己引入的，已修）

### 故障现象

启动预览后页面能渲染，但**所有按钮都点不动**。

### 根因

**两个都是我造成的**：

1. **跨行字符串断裂（主因）**：我在同步源页面时用文本替换把 `</body>` 前面插入了
   `inject.js`，但页面 JS 里有个 `writeDownloadWindow()` 函数，其拼接字符串里包含
   `'</body></html>'`。替换命中了字符串内部，把
   `+ '</body></html>';` 拆成了 `+ '` + 换行 + `</body></html>';`
   → 单引号字符串里出现裸换行 → **`SyntaxError: Invalid or unexpected token`**
   → 整个内联脚本不执行 → 页面渲染但所有事件都没绑定。

2. **`renderSkeleton` 作用域错误**：我的「切换用户」处理器调用 `renderSkeleton()`，
   但该函数定义在 `init()` 内部，外层取不到 → `ReferenceError`。

### 修复

1. 还原被破坏的字符串（`www/index.html` 与 `打工人小账本.html` 两处）。
2. `prepare-page.py` 增加**自检**：检测内联脚本里「单引号字符串跨行断裂」，
   发现就 `SystemExit` 报错并指出行号，避免再次静默产出坏页面。
3. 「切换用户」处理器改为直接调用各 `render*()` 函数（都在外层作用域），不再用 `renderSkeleton()`。

### 验证方式（重要经验）

- **`new Function(js)` 校验语法**是发现这类问题的关键 —— 光看文件大小/内容 diff 看不出来。
  语法校验必须在每次改完页面后跑一次。
- 装了 **agent-browser**（`agent-browser install`）用于真实浏览器验证；
  但其守护进程会挂起，改用**自写 CDP 探测脚本**（Node + 内置 http/net + 手写最小 WebSocket）
  驱动 `C:\Users\Administrator\.agent-browser\browsers\chrome-*/chrome.exe`，
  能收集 `Runtime.exceptionThrown` / `console.error` 并模拟点击。
- 最终验证结果：**0 运行时异常、0 console.error、43 个按钮事件均已绑定**，
  「切换用户」「添加新成员」「创建成员」「导航切页」点击均生效。

### 教训

用文本替换往 HTML 里插标签时，**绝不能用裸 `</body>` 作为锚点** ——
页面 JS 字符串里可能含有同样的片段。应改用「最后一个 `</body>`」或先定位脚本闭合位置。

## 晚间：导入去重加固（1.0.8）

### 需求

「导入数据不要出现重新导入的情况，最好数据去重」—— 重复导入同一份文件不该产生重复记录。

### 定位到的三个真实泄漏点

先用 `.workbuddy/_probe/dedup-analysis.js` 把页面里的去重公式抄出来推演，锁定：

1. **日期精度不一致（主因）**：`importFlowRows` 建索引时用
   `String(r['日期']).slice(0,10)`，但导出走 `normalizeStamp()` 会写入带时分的值。
   于是库内 `2026-10-12 12:30` 与导入的 `2026-10-12` 视为两条 → 重复导入必然新增。
   注：`overlay` 的既有注释已提到「必须截断到日」，但只做了一半（库内截、导入侧未一并归一）。
2. **备注未清噪**：前后空格 / `\r` / `\n` / `\t` / `\u00A0` 让指纹不等。
3. **备份导入完全不看「外部单号」**：只有账单导入按单号去重。
   → 同笔交易备注被改过、或「先进账单再进备份」都会重复记两笔。

### 修复

新增 3 个归一化函数 + 1 个指纹函数（定义在 `flowProps` 旁边）：

| 函数 | 作用 |
|---|---|
| `dedupText` | 去首尾空白 + 压缩连续空白 + 剔除 `\r\n\t\u00A0` |
| `dedupDate` | 一律截到「天」，抹平带时分/纯日期差异 |
| `dedupNo` | 单号去空白 + `toUpperCase()`（单号大小写不敏感） |
| `flowFingerprint` | `日期(天)\|收支\|金额(2位)\|分类\|备注` |

**两条导入路径（`importFlowRows` / `importBillRows`）统一规则**：
外部单号命中 **或** 字段指纹命中 → 跳过。
单号最强（同笔交易改备注也不重复）；指纹兜住「无单号」与「先进账单再进备份」的跨来源重复。

**刻意不做的事**：`dedupText` 不做全角/半角转换、不做大小写折叠 ——
中文备注里全角半角可能语义不同，**误合并比漏合并更糟**。只有单号折叠大小写。

### 提示语改进

整份文件全是重复时，提示改为明确结论：
「这些数据之前已经导入过，已自动去重跳过 N 条，没有重复记录产生」，
避免用户误以为「导入成功但没数据」。账单导入路径同款处理。

### 验证

- **19 项单元断言**（`.workbuddy/_probe/dedup-verify.js`）：覆盖日期精度 / 备注噪声 / 单号大小写 /
  金额浮点 / 跨来源重复，以及**反向回归**（不同日期/金额/分类/备注/收支必须仍新增）→ 全通过。
- **浏览器端到端**（`.workbuddy/_probe/dedup-e2e.js`，headless Chrome）：
  300 条第一次导入全新增，同批第二次导入 `secondAdd=0 / secondDup=300`，
  再模拟「带时分日期」第三次 `thirdAdd=0 / thirdDup=300`；
  **0 未捕获异常、0 console.error** → PASS ✅。
