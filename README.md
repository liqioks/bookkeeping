## 三、重新打包（一条命令）

页面源文件改动后，在工程目录执行：

```bat
cd /d E:\dagongrProject
python build-apk.py
```

它会依次完成三件事：

1. `prepare-page.py` —— 从源工程同步页面到 `www\index.html`（含 App 版适配）
2. `cap copy android` —— 把 `www` 复制进 Android 工程的 `assets/public`
3. `gradlew assembleDebug` —— 打包出 APK

**产物**：`android\app\build\outputs\apk\debug\app-debug.apk`

> ⚠️ 第 2 步不能省。只跑 `gradlew assembleDebug` 时，Gradle 会因为资源未变化而跳过打包，
> 拿到的会**还是上一个版本的页面**。`build-apk.py` 已把这一步固化进去。

### 只同步不打包

```bat
python prepare-page.py
npx cap sync android
```


## 四·五、2026-10-13 修复的三个问题

### 问题 1：登录后导了数据，进入界面看不到数据

**根因**：`LocalDB.query`（App 本地存储适配层）的**游标分页是假的** ——
结果超出 `pageSize`（200 条）时返回 `hasMore:true`，但 `nextCursor` 恒为 `null`。
上层 `queryOneMonth` 的翻页条件是 `hasMore && next && next!==cursor`，
`next` 为 null 时循环直接退出 → **第 201 条之后的流水被静默丢弃**。
导入的备份通常远超 200 条，所以「导入成功提示」有，但列表几乎空白。

**修复**：把 `startCursor` 当**偏移量**实现真分页，`nextCursor` 返回下一段起点字符串；
`hasMore` 按是否还有剩余数据计算。修复后 250 条可完整翻出、无重复、不串成员。

### 问题 2：需要「切换用户」（回到登录界面重新导入）

**修复**：新增「**切换用户**」按钮，**共两个入口**，行为完全一致：

| 入口 | 元素 id | 位置 |
|---|---|---|
| 侧栏 | `#navSwitchUser` | 左侧导航「我」按钮上方 |
| 驾驶舱数据卡 | `#d-switch-user` | 驾驶舱 →「数据备份与迁移」→ **紧挨「导入数据」右侧** |

两者都调用同一个函数 `switchUserOut()`：清空当前身份（`state.u` 置空 + `writeU('')`）、
清空所有按成员隔离的缓存（`flow` / `extraFlow` / `agg` / `settings` / `settingsId` / `pendingAcct`）、
把查询范围重置回本月、抹掉各页界面内容，然后打开「你是哪一位？」登录门 ——
可重新选成员、新建、或**导入新数据**。

> **注意**：`switchUserOut()` 只清内存里的身份与缓存，**不删数据库里的记录** ——
> 这只是「退出登录」，不是「清空数据」。换回原成员仍能看到自己已导入的账，
> 所以「切换用户」是安全的，不会造成数据丢失。

同时抽出 `switchToUser(u)` 统一处理「进入某成员」的全部重置动作，
避免只改一部分缓存导致「切了人但数据还是上一位的」。

> 两个入口共用同一实现（`switchUserOut`），是为了防止两处各自维护一套清理逻辑而逐渐漂移
> —— 那种情况下很容易出现「侧栏切得干净、卡片切不干净」这类只在某个入口复现的怪 bug。

### 问题 3：在首页重新导入数据，提示成功但页面数据依旧没有

**根因**：导入的流水归属**文件里那个成员的 `u`**，
而明细查询严格按当前 `state.u` 过滤。若导入的成员 ≠ 当前成员，数据其实写进去了但一条都不显示；
旧代码只弹一句「请在左下角切换过去查看」，用户很容易忽略。

**修复**：导入完成后比对归属成员，若与当前成员不一致 → **自动切换过去**并提示；
一致则正常 `reloadRange()` 刷新当前列表。

### 问题 4：重复导入仍会产生重复记录

**根因**：两条导入路径的去重口径不一致，且字段未归一化：

1. **日期精度不一致** —— `importFlowRows` 原来用 `String(r['日期']).slice(0,10)` 取库内日期，
   但导出时 `normalizeStamp()` 会写进带时分的值。于是库里有 `2026-10-12 12:30` 时，
   与导入的纯日期 `2026-10-12` 视为两条不同记录 → 重复导入必然新增。
2. **备注未归一化** —— 前后空格、`\r\n`、`\u00A0`（不换行空格）等不可见差异会让指纹不等，
   同一笔交易被当成新记录。
3. **备份导入路径完全不看「外部单号」** —— 只有账单导入按单号去重。
   所以同一笔交易若备注/分类被改过，或先进账单再进备份，就会重复记两笔。

**修复**：抽出三个归一化函数，两条导入路径统一使用：

| 函数 | 作用 |
|---|---|
| `dedupText(v)` | 去首尾空白 + 压缩连续空白 + 剔除 `\r\n\t\u00A0` 噪声 |
| `dedupDate(v)` | 一律截到「天」，抹平带时分 / 纯日期的差异 |
| `dedupNo(v)` | 外部单号去空白 + 统一大写（`WX001` 与 `wx001` 视为同一单） |
| `flowFingerprint(...)` | 组合成 `日期(天)\|收支\|金额(2位)\|分类\|备注` 指纹 |

判重规则统一为：**外部单号命中 或 字段指纹命中 → 跳过**。
单号是最强判据（同笔交易即使备注改了也不重复）；指纹兜住「无单号」以及
「先进账单（无单号）、再进备份（有单号）」这类跨来源重复。

**验证**：19 项单元断言 + 浏览器端到端（300 条连续导入两次：
`firstAdd=300 / secondAdd=0 / thirdAdd=0`，含带时分日期场景），全部通过。

**附带改进**：当整份文件全是重复时，提示语改成明确结论
「这些数据之前已经导入过，已自动去重跳过 N 条，没有重复记录产生」，
避免用户误以为「导入成功但没数据」。

## 四·六、启动开发预览（改完页面自动生效）

```bash
python serve.py            # 默认 5180
python serve.py 8080       # 指定端口
```

`serve.py` 是专为开发调页面写的静态服务（`www/` 为根），比 `python -m http.server` 多两件事：

| 特性 | 说明 |
|---|---|
| **强制禁缓存** | 所有响应带 `Cache-Control: no-store`，浏览器不会拿旧的 `index.html` |
| **自动刷新** | 注入一段轮询脚本，保存 `www/index.html` 后浏览器**自动 reload** |

> **为什么需要这个**：直接用 `python -m http.server` 时，浏览器会启发式缓存页面，
> 表现为「代码改了但界面没变，得手动刷新甚至重启服务才生效」。`serve.py` 专治这个。

> ⚠️ 注入脚本**只在开发服务里生效**（服务端内存中注入，不落盘），
> 打包进 APK 的 `www/index.html` 不含它 —— 见 `serve.py` 里 `RELOAD_SNIPPET` 的说明。

> 实现细节：用**轮询版本号**（`/__dev_version` 返回被监视文件的内容哈希）而不是 SSE。
> 最初用 SSE，服务端确实广播成功（手写 socket 客户端能收到 `data: reload`），
> 但 Chrome 的 `EventSource` 在 `http.server` 这种「无 `Content-Length` + HTTP/1.0」的响应下收不到事件，
> 于是改成轮询 —— 简单可靠，0.8 秒一次开销可忽略。

## 六、数据备份与迁移（导入 / 导出）

### 首次使用（推荐顺序）

刚装好 App 时，本地还没有任何成员。登录门里给了**两个**选择：

| 你的情况 | 怎么做 |
|---|---|
| **有备份文件**（之前导出的 xlsx） | 点「**导入 Excel 备份**」→ 成员会随备份一起导入 → 列表里出现该成员 → 点选进入，数据立刻可见 ✅ |
| **全新开始** | 点「添加新成员」建一个 → 进入空账本 |

> 关键点：导入会**连成员一起导入**。如果只导流水、不导成员，导入的记录归属的成员不在列表里，
> 就会"导入成功却看不到数据"。现在导入顺序固定为 **成员 → 设置 → 流水**。

App 里另有**两个入口**：

| 入口 | 位置 |
|---|---|
| **驾驶舱卡片** | 打开 App 的首页（今日驾驶舱）底部 → 「数据备份与迁移」卡片 |
| **侧栏按钮** | 左侧导航底部 → 「数据备份」（点击自动回到驾驶舱并定位到该卡片） |

卡片里提供：

- **导入 Excel** —— 选择 `.xlsx` 备份文件，校验 → 去重 → 写入本机
- **导出全部（Excel）** —— 汇总全部流水，生成 4 个 sheet 的文件（流水 / 月度汇总 / 设置 / 成员）
- 数据概览：已载入笔数、覆盖月份数、存储位置（本机存储 / 云端在线）

**换手机迁移**：旧机「导出全部」→ 把 xlsx 传到新机 → 新机「导入 Excel」。
同一份文件重复导入**不会产生重复记录**（两端去重规则一致）。

### 导出后文件去哪了

| 环境 | 保存方式 |
|---|---|
| **App（手机）** | 弹出系统「分享 / 保存」面板 —— 选「保存到文件」存到手机，或直接发给微信 / 网盘 |
| **网页版** | 浏览器直接下载到「下载」文件夹；若被浏览器拦截，页面会给出「保存到本机」按钮 |

> 原因：Android WebView 不支持网页里的 blob 下载，所以 App 内改走原生文件 + 系统分享面板
> （依赖 `@capacitor/filesystem`、`@capacitor/share` 两个插件）。
> 网页版则因为分享页的 iframe 沙箱没有开 `allow-downloads`，改用一个新窗口来承接下载。

### 记账时间

每条记录都带**时分秒**（精确到秒），明细列表、Excel / CSV 导出都会带上。

| 记账方式 | 记录的时间 |
|---|---|
| 手工记账 | 选「今天」→ 点保存那一刻的时分秒；选别的日期 → 当天 `00:00:00` |
| 账单导入 | 账单里的**原始交易时间**（如 `2026-09-01 12:30`，秒位补 `00`）|
| 自动记账 | 支付通知到达的时刻 |

> 说明：时间按你手机的本地时间记录，不涉及时区换算。
>
> **实现要点**：秒精度存在一个额外的 `text` 字段「记录时间」里，格式固定 `YYYY-MM-DD HH:mm:ss`。
> 原因是云端 `date` 类型字段读回时会被转成 ISO-8601 UTC 字符串（`2026-06-24T10:00:00Z`），
> 经时区换算后秒位可能与写入时不一致；`text` 字段是无损透传，所以秒精度必须走它。
> 原「日期」仍是 `date` 类型，继续负责区间筛选与排序；读取时优先取「记录时间」，取不到再回退「日期」。
>
> ⚠️ **历史数据**：1.0.11 之前记的账从未存过真实时分秒，读出来只会是 `00:00:00`，无法追溯恢复。

### 今日消费额度（超额提醒）

驾驶舱里有一张「今日消费额度」卡，用来管住当天的花销：

| 能力 | 说明 |
|---|---|
| 当日总消费 | 大字显示今天已花多少；已超额度时**变红**，未超时**绿色** |
| 设置额度 | 输入框填「当日最高额度 ¥」→ 点「保存额度」（填 `0` 或留空 = 关闭提醒） |
| 进度条 | 按 `已花 / 额度` 填充，超额后整条变红 |
| 超额弹窗 | 当天消费**首次**超过额度时弹窗提示；此后**每一笔**新的超额支出都会再弹一次 |
| 今日不再提醒 | 弹窗里点「今日不再提醒」→ 写今天的日期作为静音标记，当天不再弹 |
| 每日刷新 | 静音标记是**日期字符串**，第二天 `todayStr()` 不等就自动失效，无需任何定时任务 |

> 触发点覆盖 5 条记账路径：手工记账、驾驶舱「现在记一笔」、自动记账「补记」、通知监听记账（单笔）、导入。
> 其中手工记账额外判断「选的是不是今天」——补记昨天的账不会触发今天的超额提醒。
> 判定只在 `收支类型 = 支出` 时生效（额度是花钱上限，不是收入上限）。
>
> **实现坑**：`doSaveSettings()` 只持久化 `DEFAULT_SETTINGS` 里已声明的 key，
> 所以新增的设置项**必须同时加进 `DEFAULT_SETTINGS` 和 `NUM_SET`**，否则保存会静默失败。
> 本功能用到两个字段：`当日消费额度`（number）、`超额提醒静音日期`（text）。

### 金额精度

所有金额**保留两位小数**（精确到分）：`¥0.10`、`¥1.88`、`¥10,580.00`。
账单解析、自动记账、手工录入三条路径都会在写入前取整到分，不会出现 `0.1 → 0` 这种取整问题。

### 导入微信 / 支付宝账单

页面上的「**导入数据**」会自动识别文件类型，不用手动选：

| 文件 | 走哪条通道 |
|---|---|
| 本账本导出的 `.xlsx` 备份 | 备份导入（成员 + 设置 + 流水）|
| 微信 / 支付宝导出的账单（`.csv`，微信的 `.xlsx` 也可）| 账单导入 |

**怎么拿账单文件**

- 微信：微信 App → 我 → 服务 → 钱包 → 右上角 `···` → 账单 → 常见问题 → 下载账单 → **用于个人对账** → 选时间段 → 填邮箱 → 邮件里下载压缩包（解压码在「微信支付」公众号里）→ 解压得到 CSV
- 支付宝：支付宝 App → 我的 → 账单 → 右上角 → 开具交易流水证明 → 用于个人对账 → 自定义时间 → 邮箱收取

**导入时会自动做这些**

1. 跳过文件前面的说明行，自动找到真正的表头；
2. 自动识别编码（微信 UTF-8 / 支付宝 GBK）；
3. 按「交易时间 / 收-支 / 金额 / 交易对方 / 商品 / 交易单号 / 当前状态」映射字段；
4. 按关键词**自动分类**（美团→吃饭、滴滴→交通、淘宝→购物、房租水电→房租…）；
5. **按交易单号去重** —— 同一份账单导两遍不会重复；退款 / 关闭 / 撤销的交易自动跳过；转账理财等中性交易默认跳过。

> 账单记录会归到**当前选中的成员**，所以请先进页面再点「导入数据」。

### 自动记账（通知监听，仅 Android）

开着 App 的「自动记账」后，微信 / 支付宝 / 云闪付 / 各家银行 App 推送的**支付通知会被自动读取并记一笔**，不用手动录入。

**开启步骤**

1. 打开 App → 驾驶舱底部「**自动记账（通知监听）**」卡片 → 点「去系统设置开启」；
2. 系统会跳到「通知使用权」页面 → 在列表里勾选「**小账本 · 自动记账**」；
3. 返回 App，状态变成「监听中」即生效。

卡片里还有：

- **暂停 / 恢复** 开关（暂停后仍然读通知，但不记账）；
- **最近捕获** 列表 —— 显示自动记下的每一笔；识别不了的通知也会列出原文，方便排查。

**支持的来源**：微信、QQ、支付宝、云闪付，以及招商 / 工商 / 建设 / 农业 / 中国 / 交通 / 邮储 / 平安 / 民生 / 浦发 / 广发 / 光大 / 中信 / 银联等银行 App。

**识别规则**：自动提金额、判收支方向、提商户，并按关键词自动分类（星巴克→吃饭、地铁→交通、京东→购物…）。
同一条通知 5 分钟内只记一次（系统会重复推送）。

**App 在后台也能记**

Android 会在 App 退到后台时暂停网页里的脚本执行。所以通知不是直接丢给页面，而是**先存在 App 本地队列**，
等你回到 App（或刚选完成员）时自动补记 —— 付款那一刻 App 在后台也不会漏。

**卡片上的四项状态**

| 显示 | 含义 | 怎么办 |
|---|---|---|
| 状态 = 未开启 | 还没在系统里勾选授权 | 点「去系统设置开启」 |
| 服务 = 未连接 | 勾了，但系统还没连上 | 退到桌面再打开 App |
| 待补记 N 条 | 后台攒了通知，马上补记 | 等提示即可 |
| 最近捕获里有「未识别」 | 收到了但没匹配上规则 | 把原文发我，我调规则 |

**两点注意**

- **仅 Android**：iOS 没有「通知使用权」这类系统能力，做不到；
- **别和账单导入叠用**：自动记账的记录没有交易单号，之后导入同期账单可能会重复。建议二选一。
  （如果两家都要用，导完账单后到「最近捕获」或明细里核对一下。）

> 记账页（10 秒记账 → 记录明细）里也保留了同样的导入 / 导出按钮。

## 七、安装到手机

1. 把 `打工人小账本-v1.0-debug.apk` 传到手机（微信 / 数据线 / 网盘）
2. 手机设置里允许「安装未知来源应用」，点击 APK 安装
3. 首次打开会显示「**你是哪一位？**」→ 点「添加新成员」建一个即可开始记账
4. 数据存在**手机本地**（IndexedDB），不联网也能用

## 八、注意事项

- 当前是 **debug 版 APK**（自用/测试够用）。若要正式分发，需配置 **release 签名**（keystore）。
- 数据在 App 私有存储里，**卸载 App 会清除**；重要数据请用「数据备份与迁移」卡片里的「导出全部（Excel）」备份。
- 换手机迁移：旧机「导出全部」→ 新机「导入 Excel」。
- App 内页面与网页版**共用同一份代码**，功能一致（除了成员选择走本机选人/新建）。
